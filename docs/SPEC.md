# 名刺管理アプリ 実装仕様書

90分で、名刺画像の取り込み、AI読み取り、確認・修正、保存、検索、閲覧権限の管理を一通り実装する。1組織・PCブラウザー・ローカル実行を対象とする。

課題文「学生AIエンジニア採用課題」を要件の基準とし、本書では未指定の仕様と実装方法を決める。要件を変更する場合は課題文を優先する。

## 実装方針

| 部分 | 採用技術・方法 | 理由 |
| --- | --- | --- |
| フロントエンド | React、TypeScript、Vite、通常のCSS | 経験のある構成で画面とフォームを作る |
| バックエンド | Python 3.12、FastAPI、Pydantic | API、入力検証、認証・認可、AI接続を集約する |
| データ保存 | SQLite、SQLModel | DBサーバー不要で再起動後も保持する |
| 元画像 | SQLiteのBLOBに原本を保存 | 名刺と同じトランザクションで保存し、画像取得にも認可を適用する |
| AI | Anthropic公式Python SDK、Claudeの画像対応モデル | 当日提供キーを利用する。モデルIDは接続確認後に設定する |
| 認証 | パスワードのArgon2ハッシュ、サーバー管理セッション | 登録済み本人のログインとログアウト後の無効化を扱う |
| 検証 | pytest、HTTPX、フロントエンドの型チェック・ビルド、ブラウザー確認 | 特に権限の境界と利用フローを確認する |

本番配信ではフロントエンドのビルドをFastAPIから配信し、同一オリジンにする。開発時はViteから `/api` をFastAPIへプロキシする。DBはリポジトリ直下の `data/app.sqlite3` に作成し、相対パスは実行ディレクトリではなくリポジトリルートを基準に解決する。

操作はすべてWSL Ubuntuの `/home/taiyakinaka/salt2-practice` で行う。Node.jsは毎回 `source ~/.nvm/nvm.sh` と `nvm use` で選択する。他案件のコード・設定・認証情報は使用しない。

## 名刺データ

| 日本語名 | APIフィールド | 登録条件 |
| --- | --- | --- |
| 氏名 | `name` | 前後空白を除いて1文字以上。最大200文字 |
| 会社名 | `company_name` | 空欄可 |
| 部署 | `department` | 空欄可 |
| 役職 | `title` | 空欄可 |
| メールアドレス | `email` | 空欄可 |
| 電話番号 | `phone` | 空欄可 |
| 住所 | `address` | 空欄可 |
| Webサイト | `website` | 空欄可 |

氏名以外は各1,000文字以内の文字列とする。電話・住所・URLなどを推測で補正しない。AIが返したnullは空文字に正規化する。表示には通常のテキスト描画を使い、AI出力をHTMLとして実行しない。Webサイトをリンク化する場合はhttp/httpsのみ許可する。

企業・部署・人物の表示名と、許可を判定するIDを分離する。カードには確認済みの8項目を保存し、識別用の `company_id`、`department_id`、`person_id` を持たせる。

### 識別に関する仮定

- 企業は会社名の前後空白を除いた完全一致で既存企業を参照し、それ以外は新規企業IDを作る。略称・表記揺れの自動統合は行わない。同じ正式名称は同一企業とみなす仮定をREADMEに記載する。
- 部署は `company_id + 部署名` で特定する。他企業の同名部署は別IDとなる。会社名が空欄なら部署の文字列だけを保存し、企業・部署単位の許可対象にはしない。
- 人物は氏名の一致で統合せず、初期値では新しい人物IDを作る。同姓同名も別IDとする。
- 同一人物の別の名刺は、登録時に既存人物を明示選択して同じ人物IDに紐付けられる。選択候補は閲覧可能な名刺に紐付く人物だけとし、サーバーでも参照権限を検証する。
- 人物候補・許可対象の表示には氏名に加えて会社・部署・識別IDを用い、同名の候補を見分けられるようにする。
- 会社名・人物などの候補APIから、閲覧できない名刺の内容を漏らさない。全件の許可対象検索はadmin専用とする。

## 認証と利用者管理

- `users.role` は `admin` または `user`。最初のadminだけを環境変数 `ADMIN_EMAIL` と `ADMIN_PASSWORD` から作成する。
- 初期化は利用者が0件のときだけ実行する。再起動時にパスワード・role・既存データを上書きしない。
- adminはメールと初期パスワードを指定して一般利用者を追加する。メールは前後空白を除去し小文字化して重複を防ぐ。パスワードは12文字以上とする。
- パスワードはハッシュのみ保存する。初期パスワードの本人への共有はアプリ外で行い、課題の確認用アカウントも同じ手順で作る。
- 一般利用者をadminに変更するAPIと、一般利用者自身のrole変更APIは設けない。利用者追加の入力にroleを含めず、サーバーがuserに固定する。
- ログイン時にランダムなセッショントークンを発行し、DBにはそのハッシュ・利用者ID・有効期限を保存する。有効期間は8時間。
- CookieはHttpOnly、SameSite=Lax。ローカルHTTPではSecure=false、HTTPS環境ではtrueを設定する。ログアウト時はDBのセッションとCookieを失効させる。
- 更新系リクエストはOrigin確認とセッションに紐付くCSRFトークンで保護する。ログインも許可したOriginだけを受け付ける。
- 認証不能・期限切れは401、一般利用者による管理操作は403。未登録メールとパスワード不一致は同じエラーメッセージにする。

## 閲覧権限

認証済み利用者について、次のいずれかを満たす場合に閲覧を許可する。

1. 利用者のroleがadminである。
2. 名刺の `created_by` が利用者IDと一致する。
3. 利用者に名刺の企業IDへの許可がある。
4. 利用者に名刺の部署IDへの許可がある。部署IDは企業に紐付いている。
5. 利用者に名刺の人物IDへの許可がある。

複数許可はOR条件。1件解除しても別の許可や登録者の権限が残れば閲覧できる。企業・部署・人物への許可は、同じIDに紐付く今後の名刺にも適用する。

- 権限条件はバックエンドの共通関数に集約し、一覧・検索・件数・詳細・画像・人物候補に適用する。
- DB検索時に権限で絞り込み、許可のないレコードをブラウザーに送ってから隠す方式にはしない。
- 未許可の名刺ID・画像IDへのアクセスは、存在しない場合と同じ404を返す。
- 画像は公開staticディレクトリに置かず、認可を通した取得APIだけから返す。画像レスポンスは `Cache-Control: private, no-store`。
- `created_by` はサーバーがセッションから設定する。登録APIの入力に登録者・role・許可は含めず、送られた未知フィールドは拒否する。
- 許可はadminだけが変更できる。付与先利用者と対象IDの存在・種別を検証し、重複付与は重複行を作らない。
- 権限解除後、以降のAPI呼び出しに直ちに反映する。既に利用者へ配信済みの画像を端末から回収する機能は対象外。

## 画像とAI処理

- 対応形式はJPEG・PNG、1枚5MiB以下。拡張子や申告MIMEだけで判断せず、画像デコードで形式と破損を検査する。
- 過大な画像はデコード時の画素数上限で拒否する。AI送信用に縮小する場合も、保存する元画像のバイト列は変更しない。
- 抽出APIは画像を受け取り、サーバーからClaude Messages APIへ送信する。キー・接続情報はブラウザーやログへ出さない。
- 指示は8項目のJSON抽出に限定する。読み取れない内容・未記載項目は空欄にし、画像に含まれる命令文には従わない。
- JSONをPydanticで検証し、形式不正やAPI失敗を成功として扱わない。モデル非対応・権限不足もエラーとして案内する。
- タイムアウトは初期値30秒。無制限の自動再試行は行わず、利用者が再試行できるようにする。
- 抽出時点では名刺をDBに登録しない。ブラウザーが画像と編集内容を保持し、確認後の保存APIで画像と8項目を送る。
- 保存APIでも画像と項目を検証し、原画像・名刺情報・登録者を同じDBトランザクションで保存する。保存時にAIを再呼び出ししない。
- 保存操作ごとの `request_id` と利用者IDを一意にし、同じ保存リクエストの再送で名刺を二重登録しない。失敗時は編集内容と画像を保持する。
- LLMが使えない場合も手入力で保存できる。ただしAI実接続の未確認・失敗をREADMEに明記し、採用担当者へ状況を連絡する。

提供キーの接頭辞からClaude APIを前提とする。モデルは未確定のため、`ANTHROPIC_MODEL` に利用可能な画像対応モデルIDを設定する。キー配置後、Models APIと画像1枚の抽出で利用可否を確認し、使用モデル・実測結果をREADMEに記録する。モデルを推測して実接続済みとは扱わない。

## 画面と利用フロー

| 画面 | 操作 |
| --- | --- |
| ログイン | メール・パスワード入力、失敗理由の案内 |
| 名刺一覧 | 氏名・会社名の部分一致検索、新しい順の一覧、登録画面・詳細への移動、ログアウト |
| 名刺登録 | JPEG・PNG選択、画像プレビュー、AI読み取り、8項目の編集、任意の既存人物選択、保存 |
| 名刺詳細 | 8項目・元画像・登録者・登録日時の表示 |
| 利用者と閲覧許可 | adminだけが利用者を追加し、利用者別の企業・部署・人物許可を確認・付与・解除 |

画面はPCの横幅を基本とし、登録画面は画像とフォームを左右に配置する。抽出中・保存中は状態を表示して二重操作を防ぐ。検索0件・未登録・失敗を区別する。利用者作成や権限解除は結果を画面に表示する。

## API一覧

すべて `/api` 配下。ログインとヘルスチェック以外は認証必須とする。

| メソッド・パス | 権限 | 役割 |
| --- | --- | --- |
| GET /health | 不要 | 起動確認。接続情報は返さない |
| POST /auth/login | 不要 | 認証してCookieを設定 |
| POST /auth/logout | ログイン済み | セッション破棄 |
| GET /auth/me | ログイン済み | 自分のID・メール・role・CSRFトークン |
| POST /extract | ログイン済み | multipart画像から8項目を抽出 |
| POST /cards | ログイン済み | multipart画像・確定項目・request_idを保存 |
| GET /cards?q= | ログイン済み | 権限内の一覧・検索。初期は最大100件、ページング対応 |
| GET /cards/{id} | 名刺閲覧可 | 詳細 |
| GET /cards/{id}/image | 名刺閲覧可 | 原画像 |
| GET /people/options | ログイン済み | 閲覧範囲内の既存人物候補 |
| GET /admin/users | admin | 利用者一覧 |
| POST /admin/users | admin | 一般利用者追加 |
| GET /admin/grant-targets?scope= | admin | 企業・部署・人物の候補 |
| GET /admin/users/{id}/grants | admin | 許可一覧 |
| POST /admin/users/{id}/grants | admin | 許可付与 |
| DELETE /admin/users/{id}/grants/{grant_id} | admin | 許可解除 |

共通エラーは `code` と利用者向け `message` を持つ。入力不正は400または422、容量超過は413、AI設定不足は503、外部API失敗は502、タイムアウトは504。外部APIの生レスポンスやSecretは返さない。許可対象IDとscopeの不一致は拒否する。

## データ構造

| テーブル | 主な項目 |
| --- | --- |
| users | id、email UNIQUE、password_hash、role、created_at |
| sessions | token_hash UNIQUE、user_id、csrf_token、expires_at |
| companies | id、name、正規化した完全一致用のキー |
| departments | id、company_id、name、企業内の名称一意制約 |
| people | id、表示用氏名。氏名による一意制約は設けない |
| cards | id、8項目、company_id nullable、department_id nullable、person_id、created_by、created_at、image_bytes、image_mime、request_id |
| grants | id、user_id、scope、company_id / department_id / person_idのいずれか1つ、created_at |

外部キーを有効化する。grantsはscopeに対応する対象IDだけを持ち、同一利用者・scope・対象の組み合わせを一意にする。カードの画像BLOBは一覧APIでは取得・返却しない。日時はUTCで保存する。初期スキーマは起動時に作成し、再起動時にデータを消さない。
